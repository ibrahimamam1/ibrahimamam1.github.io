# ML Big Picture
The main idea behind all of machine learning is actually quite easy to understand. Imagine you have some magic black box in which you can feed any input data and the magic box after gigigling for a second gives you some prediction about that data. There are no restrictions to the type of data you can feed the magic box it could be as simple as 2D data points and as complex as text(which is just represented as very high dimensional data points), and images( yeah you guessed it, even more high dimensional data points). The predictions from our magic box can be anything from a continous number like for example the estimated price of RAM in 2050 (maybe a billion dollars for a 32GB stick), or simple a probability or a class label for example this image is a cat.

The magic black box is what we call a machine learning model and is essentially a mathematical model of how the inputs map to the output. This model is learned using statiscal techniques applied to large amounts of data and mathematical optimization of some objective function. There are three types of learning algorithms who differ by the type of data it trains on: Supervised Learning, Unsupersived Learning and Reinforcement Learning. In this blog we will focus of supervised and unsupervised learning, RL is a whole different beast who requires a post of its own(foreshadowing hehe).

## Gaussian Discriminant Analysis
GDA is a binary classification algorithm but unlike Logistic and Softmax it is what is called a Generative Learning Algorithm. Logistic Regression and Softmax are a class of learning algorithms called Discriminative learning algorithms. Discriminative because they discriminate between a number of classes by modeling the probability $p(y/x)$. Generative Learning algorithms on the other hand model the probability $p(x/y)$. Having a model for $p(x/y)$ gives them the ability to generate new data points hence the name Generative Learning algorithms.

GDA assumes the distribution for $p(x\y)$ is Gaussian. This is not a far fetched assumption as most of the data existing out there is gaussian. However If you know for a fact your data is definitely not Gaussian then GDA might fail and you probably should not use it.

## K Nearest Neighbours
KNN can be both a classification and a regression algorithm. As a classification algorithm it classifies each data point the same as the k data points that are geometrically closest to it. As a regression algorithm is predicts the mean of the k data points that are closest to it.

<ILLUSTRATIVE GRAPH HERE>

There is no learning or optimization taking place in this algorithm. Knn just stores all the training data and to make a prediction it iterates through all training examples and compute the distance between each example and the input, it then selects the k closest ones and either return the most common class among those k neighbours in a classification task or the mean value of the labels in a regression task.

## Bias and Variance Tradeoff

This is the major problem of ML models, when they do not find the optimal model they tend to either underfit or overfit. Underfiting means the model did not learn the patterns in the data properly and hence make wrong predictions. Overfitting on the other hand means the model memorised the patterns in the training data and cannot generalize to unseen data.

<GRAPH SHOWING UNDERFITTING AND OVERFITTING>

The symptom for underfiting is when the training loss is very high meaning the model cannot make predictions even on the training data it is seeing.

<Underfitting loss curve>

The symptom for overfitting is very low training loss but high training loss which means the model does very well on the data it has memorized but cannot do well on unseen data 

<Overfitting loss curve>

The reasons for underfitting include:
    - The model is too simple. Like fitting a straight line to data that has a quadratic relationship between features and target
    - Not enough training data
    - Trained for too few iterations
    - Learning rate too high 

The reasons for overfitting include:
    - The model is too complex. like fitting a polynomial to linear data. 
    - Trained for too long.

## Debugging

Many times our implementations of an ML algorithm for a certain task will not work. When that happens how can we do the debugging process? This is more of an art than a science but here are some general tips to follow:

- Perform a proper bias vs variance analysis. Plot both the training and test error and look at them carefully. You should be able to identify if it is an underfitting or an overfitting problem.

If it's an overfitting problem:
    - Simplify the model(use less features)
    - Add Regularization
    - Is your algorithm suitable?
    - Are your hyperparameters correct?

If it's an underfitting problem:
    - Get more data
    - Add number of features
    - Do more training iterations

If the above does not work here are some more things you can do :

You have to determine if your optimisation algorithm is not converging or if it is converging but you are optimising the wrong loss function. If you used a loss function J and converged to weights W1 try a seperate algorithm with a different loss function \alpha which will converge to weights W2. If \alpha(W1) > \alpha(W2) and J(W1) > J(W2) this means your loss function is not the problem. The algorithms fails to converge to optimal Weights. Check the learning rate and maybe the training data. On the other hand if \alpha(W1) > \alpha(W2) and J(W1) < J(W2) then you are optimising the wrong loss function. Change it.
